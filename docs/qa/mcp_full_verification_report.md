## 2. Честный разбор ограничений и ошибок Pyrus API (API Restrictions & Errors)

Во время прямого прогона мы столкнулись с реальными правилами и ограничениями Pyrus API:

### 1. `delete_task` — Философия Pyrus о невозможности удаления задач
* **Поведение API:** В Pyrus API v4 в принципе **отсутствует эндпоинт физического удаления задач** (`DELETE /tasks/{id}`). Задачи в Pyrus являются неизменяемым аудиторским следом и могут быть только закрыты (`finished`) или заархивированы.
* **Как отработал MCP:** Вернул точный легаси-ответ: `{"error": "Pyrus API does not support deleting tasks."}`. Это 100% соответствие спецификации.

### 2. `delete_role` — Защита от потери задач при удалении роли
* **Поведение API:** При попытке удаления роли без указания правопреемника или при передаче заблокированного сотрудника Pyrus API возвращает `500 Server Error: "Вы не можете перенаправить задачи на заблокированного сотрудника"`.
* **Требование API:** Обязательный параметр `task_receiver_id`, указывающий на **активного** пользователя, которому перейдут все задачи этой роли.
* **Результат теста:** При вызове `delete_role(id=1322389, task_receiver_id=1238106)` роль была успешно удалена со статусом `{"id": 1322389, "fired": true}`.

### 3. `create_list` — Нестандартный HTTP-глагол создания
* **Поведение API:** При отправке `POST /lists` Pyrus API возвращает `405 Method Not Allowed`.
* **Исправление:** Как и справочники (`/catalogs`), создание списков в Pyrus v4 работает через `PUT /lists`. Мы исправили HTTP-метод в `legacy_lists.py`, после чего создание списка (`ID: 2458400`) прошло мгновенно.

### 4. `update_catalog_items` — Обязательность заголовков
* **Поведение API:** При попытке обновить элементы справочника без передачи структуры колонок API возвращает `400 Bad Request: "Заголовки справочника не могут быть пустыми (empty_catalog_headers)"`.
* **Требование:** Требуется передавать `catalog_headers` вместе с массивом `items`. При соблюдении схемы обновление отработало штатно.

### 5. `create_task` — Разделение простых задач и задач по форме
* **Поведение:** Если задача создается по шаблону формы (`form_id`), поле `text` не обязательно (Pyrus сам генерирует заголовок из полей формы). Ранее в коде стояло строгое требование `arguments["text"]`, что вызывало ошибку `KeyError: 'text'`.
* **Исправление:** Сделали поле `text` опциональным при наличии `form_id`. Форменная задача `374345908` успешно создана.

### 6. `download_file` — Проверка существования ID вложений
* **Поведение API:** При запросе несуществующего файла (`file_id: 999999`) Pyrus API отдаёт `400: unrecognized_attachment_id` ("The attachment file ID is incorrect").
* **Результат теста:** MCP-сервер корректно перехватил и вернул понятную ошибку клиенту, не упав.
