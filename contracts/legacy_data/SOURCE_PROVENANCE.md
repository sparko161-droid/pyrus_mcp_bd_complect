# Legacy MCP source provenance

## Exact source captured by this project

The legacy/foreign MCP server from which the compatibility inventory was collected is:

- **MCP name:** `pyrus`
- **Endpoint:** `https://pyrus-mcp-production.up.railway.app/mcp`
- **Protocol:** MCP `2025-06-18`
- **Snapshot:** `2026-08-18T11:33:29+0400`
- **Captured inventory:** `contracts/legacy_data/inventory.json`
- **Human-readable tool catalogue:** `contracts/legacy_data/TOOLS.md`
- **API mapping generated by the project:** `contracts/legacy_data/COVERAGE.md`
- **Behavioral probing utilities:** `contracts/legacy_data/collector/`

The captured server reported **58 tools**.

The project README explains that `mcp_introspect.py` captures tool names/descriptions/schemas/annotations, while `apiscope.py` + `probe_tools.py` records actual HTTP behavior and endpoint mapping through the server's own `api_url` mechanism. This is stronger evidence than guessing mappings from tool names alone.

## What is legacy vs project-added

The original foreign MCP inventory is the compatibility baseline. The current repository also contains tools which were added or renamed during reconstruction. Those must be marked `PROJECT-ADDED` in the Pyrus contract catalogue and cannot inflate the legacy parity count.

Examples of project-added convenience capabilities include batch operations and Knowledge MCP operations.

## Important distinction

The legacy server itself was not proven to be authoritative for the Pyrus API. `COVERAGE.md` shows that it reported 58 tools but only 42/58 were mapped to documented API methods in the captured mapping. Five tools were explicitly marked as not fitting documented methods. Therefore:

```text
legacy MCP behavior != Pyrus official API specification
```

For the current product the source hierarchy is:

1. **Pyrus official API** — normative external contract.
2. **Captured foreign MCP behavior** — compatibility contract.
3. **Our implementation** — must satisfy both, with ADRs for intentional differences.
4. **Project-added tools** — extensions, explicitly separated from parity.

## Required provenance metadata for every legacy tool

```yaml
source:
  kind: legacy_mcp
  endpoint: https://pyrus-mcp-production.up.railway.app/mcp
  snapshot_at: 2026-08-18T11:33:29+0400
  protocol_version: 2025-06-18
  inventory_sha: <blob-sha-or-content-hash>
  tool_name: <name>
  tool_schema_hash: <sha256>
  behavior_evidence: <scope/log/fixture-id>
```

No task may claim exact 1:1 legacy parity without this evidence.
