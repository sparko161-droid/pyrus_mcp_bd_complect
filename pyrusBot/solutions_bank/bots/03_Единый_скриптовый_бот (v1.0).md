Единый серверный бот (`unified_bot (v1.0).ts`) представляет собой консолидированное решение, объединяющее логику трёх автономных ботов в единый вебхук-обработчик.

## Поддерживаемые формы и сценарии

Бот автоматически переключается между тремя бизнес-сценариями в зависимости от формы, в которой произошел триггер:

1. **Обращения клиентов** (`Form ID: 2445746`):
   - Интерактивный 9-шаговый опрос сбора данных обратной связи (имя, телефон, email, категория проблемы, предмет, описание, вложения, адрес торговой точки, оценка).
   - Обработка команды зова оператора.
   - Фиксация состояний в поле `technical_bot_state`.

2. **Чаты-задачника** (`Form ID: 2455918`):
   - Онбординг первичных настроек: срок (в днях), дедлайн по умолчанию и ответственный сотрудник (с подбором через Pyrus API `/members` по никнейму, email или ID).
   - Автоматическое создание задач в форме «ЗАДАЧНИК» (`Form ID: 2450073`) при поступлении новых сообщений.
   - Поддержка команд переконфигурации (`/reconfig`, `/setup`, `настройка`).

3. **Бронирование столиков** (`Form ID: 2445773`):
   - Интерактивный опрос гостей для бронирования столов и проведения мероприятий.
   - Валидация даты и времени с удержанием локального часового пояса.
   - Передача диалога оператору при запросе человека.

## Алгоритм определения формы (`detectFormScenario`)

При поступлении события Pyrus Webhook (`BotHookRequest`) единый бот определяет сценарий по двухэтапной схеме:

### 1. Первичная проверка по `form_id`
Сверяется идентификатор формы запроса:
- `form_id === 2445746` $\rightarrow$ Сценарий `feedback`
- `form_id === 2455918` $\rightarrow$ Сценарий `task_chat`
- `form_id === 2445773` $\rightarrow$ Сценарий `booking`

### 2. Резервный фолбэк по кодам полей
Если `form_id` не передано или форма кастомная, проводится рекурсивный сканирующий поиск сигнатурных полей задачи:
- При наличии полей `day_to_dl`, `dl_time` или `person_id` $\rightarrow$ `task_chat`
- При наличии полей `booking_date`, `hall_zone` или `guests_count` $\rightarrow$ `booking`
- При наличии полей `client_name`, `problem_type` или `problem_description` $\rightarrow$ `feedback`

Если ни одно условие не выполнено, бот регистрирует статус `unknown` и безопасно завершает выполнение без побочных эффектов.

## Журнал событий бота (Event Logger)

Вся хронология выполнения каждого вебхука фиксируется в **Журнале событий бота**:
- Каждая запись содержит точный штамп времени UTC (`[HH:MM:SS]`);
- В журнал заносятся: параметры задачи и формы, результаты роутинга `detectFormScenario`, тексты триггеров, результаты валидации ответов и список обновляемых полей `field_updates`;
- По окончании обработки журнал публично сохраняется в виде служебного комментария в задаче Pyrus под заголовком `📋 [ЖУРНАЛ СОБЫТИЙ БОТА]`.

## Локальное тестирование
