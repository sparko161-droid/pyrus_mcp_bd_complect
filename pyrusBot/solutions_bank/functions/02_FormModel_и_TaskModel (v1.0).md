Код: `src/lib/models/FormModel.ts` и `src/lib/models/TaskModel.ts`. Тесты — в `src/lib/tests/bank_tests.ts`.

## Суть проблемы с API Pyrus

При получении структуры формы (`client.forms.get`) или значений задачи, Pyrus не возвращает поля единым плоским списком. Поля могут быть спрятаны на нескольких уровнях вложенности:

- Внутри поля типа "Заголовок" (`group` или `title`).
- Внутри "Таблиц" (`info.columns` или `info.fields`).
- Привязаны к конкретному варианту ответа в справочнике (dependent fields).

## Решение: FormModel

Класс `FormModel` служит для рекурсивного обхода схемы формы.
Он принимает на вход сырой массив `fields` (из ответа `client.forms.get` или, если API недоступен, фоллбэк из самой задачи) и строит два плоских словаря (Map):

1. `byId` — поиск схемы поля по его числовому ID.
2. `byCode` — поиск схемы поля по его строковому коду (`code`).

### Логика обхода `childrenOf(f)`

Функция ищет детей во всех возможных местах, куда Pyrus прячет вложенные элементы:

- `f.fields`
- `f.info?.fields`
- `f.info?.columns`
- Внутри вариантов выбора (`opt?.fields` для зависимых полей)
- В `f.value.fields` (особенность данных задачи для заголовков).

Также класс берет на себя кэширование каталогов (`catalogItems`), чтобы не делать повторные запросы на справочники во время одного исполнения скрипта.

## Решение: TaskModel

Класс `TaskModel` выполняет аналогичную работу, но для **значений полей текущей задачи**.
Он обходит дерево `task.fields` и строит плоскую Map `values`: `ID поля -> Сырое значение`.
Это позволяет бизнес-логике мгновенно получать значение любого поля, не заботясь о том, лежит ли оно в корне задачи или запрятано глубоко внутри таблицы.
