## Что это

`src/lib/testing/pyrus_simulator.ts` — движок локального прогона скриптов Pyrus без деплоя: серверных ботов (`BotHookRequest` → `BotHookResponse`) и клиентских скриптов формы (`form.onChange`). Запускается через `npm run test`, входная точка — `test_runner.ts` в корне.

## Почему сеть подменяется, а не «просто не вызывается»

Бот создаёт клиента внутри себя — `new PyrusApiClient(request.access_token)`. Подменить клиент снаружи нельзя: обработчик получает только `BotHookRequest`. Зато весь `pyrus-api` ходит через глобальный `fetch`, поэтому подменяется он.

Что было до подмены: тест уходил в боевой `api.pyrus.com`, получал `401 invalid_token` и длился 7261 мс вместо 30. Тест зависел от доступности Pyrus, жёг рейт-лимит аккаунта и — главное — проверял не то: бот отрабатывал по ветке «сервис недоступен», а тест засчитывал это как успех.

## Как объявляются ответы Pyrus

```typescript
const { response, network } = await simulateServerBot(botHandler, request, {
  routes: [
    { method: "GET",  url: "/forms/888",            body: FORM_SCHEMA },
    { method: "POST", url: "/tasks/99001/comments", body: {} }
  ]
});
```

`url` — подстрока или регулярное выражение. `respond(call)` вместо `body` даёт динамический ответ, когда важно, что именно прислал бот.

## Обязательная проверка

```typescript
check("все обращения к Pyrus объявлены", network.unmatched.length === 0, network.unmatched);
```

Незаявленный маршрут получает код 599 и попадает в `network.unmatched`. Без этой проверки забытый маршрут выглядит для бота как «Pyrus недоступен»: бот уходит в аварийную ветку, тест остаётся зелёным, а расхождение вскрывается уже на боевой форме.

Сеть возвращается на место в блоке `finally` — исключение внутри бота не оставит подменённый `fetch` следующему тесту.

## Что доступно в проверках

| Что | Зачем |
| --- | --- |
| `network.calls` | все вызовы наружу по порядку |
| `network.unmatched` | вызовы без объявленного маршрута |
| `network.callsTo(url)` | вызовы к конкретному адресу — «бот дописал комментарий?» |
| `executionTimeMs` | косвенно ловит реальный сетевой вызов: локальный прогон укладывается в десятки миллисекунд |

## Клиентские скрипты формы

`MockFormContext` собирает подписки `form.onChange(...)` и прогоняет их через `simulateChange(values)`. Сети там нет вовсе: `getCatalog` отдаёт то, что положили в `mockCatalog(id, items)`.

## Код возврата

Провал проверки выставляет `process.exitCode = 1`, поэтому `npm run check` останавливается. До этого раннер печатал ошибку в консоль и завершался успешно — сломанный бот проходил проверку.
