# Банк функций (Pyrus Shared Library)

Переиспользуемые модули, из которых собираются серверные боты и клиентские скрипты Pyrus.

> **Правило анти-дупликации**: прежде чем писать новую служебную функцию, проверьте, нет ли её здесь. Документация блоков — в Базе знаний, раздел `Банк решений → Функции` (`solutions_bank/functions/`).

## Главное ограничение: код должен пережить вставку в Pyrus

Серверный скрипт Pyrus — **один файл**, и сторонние npm-пакеты в нём **не работают**: доступны только `pyrus-api` и стандартная библиотека Node.js. Поэтому банк — не библиотека, которую подключают, а **источник для сборки**: нужные блоки копируются в файл бота, а строки `import` из соседних модулей при этом убираются.

Отсюда два правила:

1. Ни один модуль банка не импортирует ничего, кроме `pyrus-api`, стандартной библиотеки и соседних модулей банка. Проверяется машиной — тест «банк функций не тянет сторонних зависимостей» в `npm run check`.
2. В шапке каждого модуля перечислено, что придётся скопировать вместе с ним (строка «Зависимости при вставке в Pyrus»).

## Состав

| Модуль | Что внутри | Зависимости при вставке |
|---|---|---|
| `models/FormModel.ts` | Рекурсивный разбор схемы формы: индексы `byId` и `byCode`, варианты ответа, кэш каталогов | `utils/values.ts` |
| `models/TaskModel.ts` | Плоская карта `id → значение` по всей задаче, включая вложенные поля | `models/FormModel.ts` |
| `utils/values.ts` | `isEmptyValue`, `valueChoiceId`, `valueDisplay` — разбор значений Pyrus | нет |
| `utils/visibility.ts` | `evaluateCondition`, `isFieldVisible` — исполнение `visibility_condition` | `values`, `FormModel`, `TaskModel` |
| `utils/parsers.ts` | `findBestMatch`, `pickOption`, `parseCheckmark`, `parsePhone`, `parseNumber`, `parseTime` | нет |
| `utils/comparisons.ts` | `same_value`, `copy_by_value` — сравнение значений перед записью | нет |
| `utils/catalogs.ts` | `get_values_for_catalog` — поиск строк справочника | `models/FormModel.ts` (тип) |
| `api/ExtendedClient.ts` | Клиент с кэшем форм, каталогов и задач; накопление ошибок | `models/FormModel.ts` |
| `testing/pyrus_simulator.ts` | Локальный прогон ботов и формных скриптов, подмена сети | нет |
| `testing/assert.ts` | Проверки для локальных тестов | нет |
| `tests/bank_tests.ts` | Тесты банка, запускаются из `test_runner.ts` | — |

## Почему часть имён в snake_case

`same_value`, `copy_by_value`, `get_values_for_catalog` названы так же, как в шаблонных ботах Pyrus. Код серверных скриптов переносится между репозиторием и редактором Pyrus копированием, и переименование ломало бы узнаваемость у инженеров, которые видят эти функции в чужих ботах. Классы и всё, что написано с нуля, — в обычном для TypeScript стиле.

## Правила добавления кода сюда

1. **Никакой бизнес-логики конкретных форм.** Только универсальные алгоритмы: коды полей и ID форм остаются в боте клиента.
2. **Строгая типизация.** Никаких неявных `any` в сигнатурах.
3. **Без побочных эффектов.** Функция не мутирует то, что ей передали: `same_value` из шаблонного бота Pyrus писала `unchecked` прямо во входное поле, и сравнение меняло задачу.
4. **Тест обязателен.** Блок без теста в банк не попадает — тесты живут в `tests/bank_tests.ts` и запускаются через `npm run test`.
5. **Обновить документацию.** Раздел `solutions_bank/functions/` и его `История_изменений` — Фундаментальные правила 1 и 2.
