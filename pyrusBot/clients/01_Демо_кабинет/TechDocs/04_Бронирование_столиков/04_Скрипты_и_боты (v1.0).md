- **Тип:** Серверный бот Pyrus API (`BotHookRequest` -> `BotHookResponse`).
- **Исходный код:** [`booking_bot (v1.0).ts`](file:///c:/Users/KirillSM/Documents/Pyrus/pyrusBot%20%282%29/pyrusBot/clients/01_%D0%94%D0%B5%D0%BC%D0%BE_%D0%BA%D0%B0%D0%B1%D0%B8%D0%BD%D0%B5%D1%82/Forms/04_%D0%91%D1%80%D0%BE%D0%BD%D0%B8%D1%80%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D0%B5_%D1%81%D1%82%D0%BE%D0%BB%D0%B8%D0%BA%D0%BE%D0%B2/scripts/booking_bot%20%28v1.0%29.ts).
- **Форма:** 2445773 («Бронирование столиков»).
- **Техническое поле состояния:** `technical_bot_state` (ID 20).

### Принцип работы

1. **Загрузка схемы:** бот считывает полные метаданные формы `formId` через `client.forms.get()`. В случае сетевого сбоя структура восстанавливается из `task.fields`.
2. **Чтение состояния:** состояние читается из JSON в `technical_bot_state`.
3. **Фильтрация триггеров:** бот проверяет `last_event_key` для дедупликации вызовов.
4. **Проверка триггеров перевода на человека:** если комментарий содержит слова «оператор», «человек», «менеджер» или превышен лимит 3 ошибок, диалог передаётся человеку.
5. **Валидация и переход к следующему шагу:** ответ гостя распознаётся (телефон, email, варианты из каталогов 303729, 303727, 303731, число, время), записывается в соответствующее поле, после чего подбирается следующий видимый шаг с учётом `visibility_condition`.
6. **Завершение:** при заполнении всех шагов бот отправляет итоговое благодарственное сообщение, ставит статус `Status` = 1 («Новая») и `finished: true`.
