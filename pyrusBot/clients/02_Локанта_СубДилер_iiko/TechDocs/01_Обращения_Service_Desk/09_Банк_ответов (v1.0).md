## Тексты бота

Реплики заданы в коде бота. Изменение любой — правка файла, повышение версии и запись в историю изменений.

| Ситуация | Текст или содержание |
| --- | --- |
| Выбор заведения | Пронумерованный список известных заведений клиента с пунктом «ДРУГОЕ ЗАВЕДЕНИЕ» |
| Найдено несколько заведений по ИНН | Список с дополнительным пунктом «Добавить ВСЕ найденные заведения» |
| Некорректный CRMID | «Пожалуйста, введите корректный CRMID (не менее 5 цифр).» |
| Ответ не «да» и не «нет» | «Пожалуйста, ответьте '1' (Да) или '2' (Нет).» |
| Карточка клиента создана | «Рады знакомству! Мы создали для Вас карточку клиента.» |
| Класс обращения | Список: 1 — Консультация, 2 — Удалённо, 3 — Выезд |
| Приоритет | Список с пояснениями: «решить сегодня», «в течение 12 часов», «проблема не критична, нужно разобраться», «проблема срочная — невозможен расчёт гостей». **Шаг выключен, клиенту не показывается** |

## Служебные комментарии

Не видны клиенту, уходят без указания канала:

| Ситуация | Текст |
| --- | --- |
| Телефон обновлён из заявки | «Контактный номер телефона обновлён из заявки Service Desk» |
| Телефон обновлён клиентом | «Номер телефона обновлён пользователем из мессенджера» |
| Ошибка создания карточки | «Не удалось создать карточку клиента в Pyrus API» |

## Правила формулировок

- Ответ номером пункта поддерживается везде, где бот показывает список.
- Бот не называет сроков решения обращения: срок определяется приоритетом, а приоритет ставит сотрудник.
- При технической ошибке клиент видит нейтральный текст, подробности уходят во внутренний комментарий.

## Требует уточнения у заказчика

- Нужны ли шаблоны быстрых ответов оператора и для каких ситуаций.
- Согласованы ли формулировки бота с тем, как принято общаться с клиентами (обращение, тон).
