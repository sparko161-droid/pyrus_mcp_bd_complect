База знаний — общий хаб между инженерами. У каждого своя локальная копия проекта; расходится всё через git и через синхронизатор.

## Как определяется направление

Сравниваются три состояния: хэш тела на диске, `synced_hash` из YAML-заголовка (каким тело было при последней синхронизации) и `updated_at` статьи в Pyrus.

| Локально | В Pyrus | Действие |
|---|---|---|
| не менялось | не менялось | `SKIP` |
| изменено | не менялось | `PUSH` |
| не менялось | изменено | `PULL` — локальный файл перезаписывается |
| изменено | изменено | `CONFLICT` — прогон останавливается |

Если у документа нет `synced_hash` (статья заведена до перехода на заголовки либо файл перегенерирован), доказать изменение на стороне Pyrus нечем — локальная версия принимается за истину и уходит в `PUSH`.

## Заголовок документа

```yaml
---
title: "Спецификация полей"
version: "1.2"
audience: tech          # user | tech | internal
pyrus_id: "BsIC0n5GTbn"
pyrus_parent: "PCeuQb9IAy8"
synced_at: "2026-08-07T13:06:42.000Z"
synced_hash: "sha256:..."
---
```

`pyrus_id`, `pyrus_parent`, `synced_at`, `synced_hash` ведёт синхронизатор — вручную не трогать. Инженер отвечает за `title`, `version` и `audience`.

## Структура

- **`_index.md`** — это тело САМОГО раздела в Pyrus, а не отдельная статья. В нём живёт оглавление со ссылками на соседние файлы; синхронизатор заменяет ссылки вида `](файл.md)` на реальные адреса статей.
- **Статьи с исходным кодом (`<script>.ts.md`)** — создаются скриптом `npm run mirror:scripts` для каждого `.ts` файла ботов и формных скриптов, помещаются в раздел «Формы и скрипты» / «Скрипты» с `audience: tech` и выгружаются как отдельные статьи Базы знаний Pyrus.
- **Любой другой `.md`** — вложенная статья.
- **Пустой `_index.md`** пропускается: Pyrus отклоняет пустое тело. Раздел без оглавления попадёт в отчёт как нарушение Фундаментального правила 2.

## Заголовки в теле


Pyrus сам подставляет `# <title>` в начало тела при отдаче через API. Поэтому **H1 в теле документа запрещён вообще** — иначе в статье будет два одинаковых заголовка подряд, а при `PULL` этот заголовок начнёт накапливаться. Тело начинается сразу с текста или с подзаголовков H2/H3.

## Нумерация

Номера вычисляются при синхронизации из префиксов имён папок и файлов, руками их никто не ведёт:

```
14           корень клиентской документации
14.01        клиент          (clients/01_Демо_кабинет)
             аудитория без номера (UserDocs / TechDocs / Forms)
14.01.1      форма           (01_Заказы_тортов)
14.01.1.2    статья          (02_Спецификация_полей)
```

Уровень аудитории номера не получает, но передаёт номер клиента дальше — поэтому одна и та же форма имеет один номер и в пользовательской, и в технической ветке.

## Команды

```bash
npm run kb:sync        # синхронизация
npm run kb:sync:dry    # посмотреть, что произойдёт, без записи
npm run kb:dump        # дерево Базы знаний
```

## Конфликты

Сливать молча нельзя. Рядом с файлом появляется `<имя>.remote.md` с версией из Pyrus: сравнить, слить вручную, удалить `.remote.md`, запустить синхронизацию снова.

## Коды возврата

`0` — успех, `1` — были ошибки обращения к Pyrus, `3` — есть неразрешённые конфликты. Ненулевой код означает, что синхронизация неполная.
