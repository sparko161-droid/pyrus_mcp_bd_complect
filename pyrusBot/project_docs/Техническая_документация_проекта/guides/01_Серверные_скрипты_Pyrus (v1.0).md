## 1. Концепция и архитектура серверных скриптов Pyrus

**Серверный скрипт** — это бот Pyrus с привязанным к нему кодом на TypeScript, который автоматически исполняется на стороне облачной или безоблачной (Datacenter) инфраструктуры Pyrus при возникновении события в задаче (например, при добавлении комментария, изменении полей или переходе этапа).

### Ключевые преимущества серверных скриптов:
- **Без собственного сервера**: не требуется разворачивать сторонний сервер, выделять публичный IP-адрес или настраивать веб-сервер/SSL-сертификаты.
- **Быстрый старт**: код редактируется и запускается прямо в интерфейсе Pyrus за несколько секунд.
- **Встроенные библиотеки**: предустановленный SDK `pyrus-api` и доступ к стандартным модулям Node.js.
- **Автоматическая авторизация**: Pyrus передаёт одноразовый/сессионный `access_token` при каждом вызове бота.

## 2. Официальные ограничения и лимиты исполнения

При проектировании логики бота необходимо строго соблюдать ограничения среды Pyrus Server Scripts:

| Параметр / Ресурс | Ограничение / Условие | Следствие для разработки |
| --- | --- | --- |
| **Язык программирования** | TypeScript / JavaScript | Полный синтаксис TS, интерфейсы, типизация. |
| **Среда исполнения** | Node.js | Доступны встроенные модули Node.js (`crypto`, `path` и т.д.). |
| **Библиотека API** | Предустановлена `pyrus-api` | Импорт через `import { BotHookRequest, BotHookResponse, PyrusApiClient } from "pyrus-api"`. |
| **Сторонние npm-пакеты** | **Не поддерживаются** | Нельзя устанавливать `lodash`, `axios` и т.д. Использовать `fetch` / `http(s)` / stdlib. |
| **Сетевые запросы** | Разрешены (HTTP / HTTPS) | Можно делать запросы к Pyrus API и внешним REST API / сервисам. |
| **Файловая система** | **Запись на диск запрещена** | Файлы хранятся только в RAM; перенос файлов через `files.download()` / `files.upload()`. |
| **Сохранение состояния (State)** | **Stateless** (без сохранения между запусками) | Нельзя надеяться на глобальные переменные. Состояние диалога/бота хранить в полях Pyrus. |
| **Таймаут исполнения** | **60 секунд** (платный тариф), **1 секунда** (бесплатный тариф) | При долгих вычислениях сначала возвращать код/ответ, затем дорабатывать асинхронно через API. |
| **Лимит частоты запусков** | **Максимум 10 запусков за 10 секунд** на бота | Не допускать каскадных loops комментариев (бот отвечает на свой же комментарий). |
| **Оперативная память (RAM)** | **256 МБ** | Ограничивать загрузку крупных файлов и реестров в память. |

> [!CAUTION]
> **Критическое правило асинхронности Node.js**: Выполнение скрипта прерывается **сразу**, как только основная функция-обработчик возвращает результат (или резолвит Promise). Все незавершённые незаавейченные фоновые операции (`doSomethingAsync()` без `await`) **принудительно уничтожаются**. Все асинхронные вызовы вызывать строго через `await` или `Promise.all()`.

## 3. Права доступа и административное управление ботами

### Права на создание и управление ботами в организации
1. **Право «Управляющий интеграциями»** (или «Администратор»):
   - Обязательно для пользователя, который создаёт, активирует, останавливает или удаляет ботов в разделе **Боты**.
   - Позволяет изменять профиль любого бота организации.
2. **Администратор конкретного бота**:
   - Сотрудник с правами «Управляющий интеграциями» может назначить в профиле бота конкретных сотрудников его **Администраторами**.
   - Администратор бота может изменять настройки бота, править код серверного скрипта, менять секретный ключ и управлять списком других администраторов этого бота.
   - Администратор бота **не может** менять системные права бота как пользователя Pyrus.

### Права самого бота как пользователя Pyrus
Бот выступает как виртуальный сотрудник организации со своим `user_id` и email (`bot@<guid>`).
- **Доступ к формам и задачам**: Чтобы бот мог читать задачу или изменять поля, бот должен быть участником формы (с правами «Заполнение», «Редактирование» или «Администрирование») или быть явно добавлен в задачу.
- **Дополнительные системные права бота**:
  - **Права «Управляющего»**: требуются ботам, которые создают или синхронизируют справочники (`catalogs.create`, `catalogs.sync`, `update_catalog`).
  - **Права «Руководителя»**: требуются для сбора обобщённой статистики через API.

### Настройки профиля бота
- **Настройки (JSON / Текст)**: произвольная конфигурация бизнес-логики (`request.bot_settings`).
- **Часовой пояс и локаль**: определяют нормализацию дат и времени.
- **Передаваемые комментарии**: выбор режима — «Все комментарии» или «Только последний комментарий» (позволяет существенно экономить трафик и RAM).
- **Пауза бота**: тумблер «Отключено» мгновенно останавливает обработку входящих событий.

## 4. Контракт вызова и структура данных

Точкой входа серверного скрипта является функция, экспортируемая по умолчанию (`export default`).

### Формат входящего запроса `BotHookRequest`

```ts
import { BotHookRequest, BotHookResponse, PyrusApiClient } from "pyrus-api";

export default async function(request: BotHookRequest): Promise<BotHookResponse> {
  const {
    task,             // Объект задачи (со свойствами id, form_id, fields, comments, approvals и т.д.)
    task_id,          // Числовой ID задачи
    access_token,     // Временный токен авторизации (действителен 5 минут для Pyrus API)
    user_id,          // Системный ID самого бота в Pyrus
    api_url,          // Базовый URL Pyrus API (например, "https://api.pyrus.com/v4/")
    files_url,        // Базовый URL файлового сервиса Pyrus
    bot_settings,     // Текст или распарсенный JSON из поля «Настройки» в профиле бота
    text              // Текст последнего комментария (в контексте диалоговых ботов)
  } = request;

  // Бизнес-логика...
  return null;
}
```

### Формат возвращаемого ответа `BotHookResponse`

Функция может вернуть `null` / `undefined` (если никаких действий над задачей производить не требуется) либо объект комментария, содержащий инструкции по изменению задачи:

```ts
return {
  text: "Текст ответа или сервисного комментария",
  field_updates: [
    { id: 1, value: "Новое значение" },
    { code: "status", value: { choice_id: 2 } }
  ],
  approval_choice: "approved", // "approved" | "rejected" | "acknowledged"
  approvals_rerequested: [[101, 102]], // Двумерный массив ID пользователей для перезапроса виз
  subscribers_added: [{ id: 501 }],
  subscribers_removed: [{ id: user_id }],
  channel: { type: "telegram", phone: "+79000000000" }, // Канал связи в диалоговом боте
  skip_notification: true // Скрыть уведомления об изменениях
};
```

## 6. ExtendedClient: Карта штатных методов и псевдополей

Класс `ExtendedClient` оборачивает `PyrusApiClient`, автоматически кэширует метаданные форм, каталоги и профили, а также обогащает входящую задачу удобными картами `task.named_fields` и `row.named_cells`.

### Основные методы `ExtendedClient`

```ts
const bot = new ExtendedClient(request.access_token, request.user_id);
const task = await bot.fix_task(request.task);
```

| Метод | Назначение | Особенности и нюансы |
| --- | --- | --- |
| `fix_task(task)` | Обогащает задачу картами `named_fields`, `all_fields` | Вызывать сразу при входе для задачи из `request.task`. |
| `get_form(id)` | Загружает и кэширует структуру `ExtendedForm` | Для получения варианты выбора `options`, типов и названий колонок. |
| `get_catalog(id, update?)` | Загружает и кэширует элементы каталога | `update = true` — насилительный сброс кэша. |
| `get_task(id, update?)` | Загружает свежее состояние задачи из API | Если задачу могли изменить параллельные боты или пользователи. |
| `comment_task(id, comment)` | Нормализует поля, обрабатывает псевдополя, отправляет комментарий | **Основной способ изменения задач.** Автоматически конвертирует `$assignee`, `$close_state`, `$due`. |
| `create_task(request)` | Создаёт новую задачу и возвращает `ExtendedTask` | При создании задач вручную вне CopyBot. |
| `get_registry_with_fix(formId, req?)` | Загружает реестр задач с заполненными `named_fields` | Для поиска существующих задач. Задачи реестра не содержат комментариев. |
| `prepare_approval_list(task)` | Возвращает `{ этап: { person_id: approval_choice } }` | Быстрый срез решений текущих согласующих. |
| `get_approval_history(task, list)` | Собирает полную историю виз с датами и авторами | Для заполнения таблиц листа согласования. |
| `get_multiple_choice_dict(code, task?, formId?)` | Возвращает карту `{ "Название варианта": choice_id }` | Исключает удалённые варианты. Использовать перед записью в `multiple_choice`. |
| `add_row_to_table(table, tableId, formId, taskId)` | Добавляет новую строку в таблицу с `named_cells` | Не собирать строки таблицы вручную. |
| `fix_task_comments(task)` | Парсит историю комментариев и добавляет `named_fields_changes` | Обязателен перед откатом или анализом истории полей. |
| `restore_last_values(...)` | Восстанавливает предыдущие/последние значения полей | Позволяет узнать, что изменилось в текущем комментарии. |

### Системные псевдополя `ExtendedClient`

Вы можете читать и переносить эти псевдополя так же, как обычные поля задачи:

| Код псевдополя | Назначение | Управляемое? | Нюансы обработки |
| --- | --- | --- | --- |
| `$task_id` | Числовой ID задачи | Только чтение | — |
| `$task_link` | Гиперссылка на задачу в Pyrus | Только чтение | — |
| `$close_state` | Состояние закрытия задачи | **Да** | `"checked"` закрывает задачу, `"unchecked"` переоткрывает через `comment_task`. |
| `$close_date` | Дата и время закрытия | Только чтение | — |
| `$assignee` | Системный ответственный за задачу | **Да** | Объект `Person` или `{ id }`. Пустое значение назначает технический ID 1730. |
| `$last_modified_date` | Дата последнего изменения | Только чтение | — |
| `$current_step` | Номер текущего этапа маршрута | Только чтение | — |
| `$parent_task_id` | ID родительской задачи | Только чтение | — |
| `$due`, `$due_date` | Срок выполнения задачи | **Да** | Обрабатываются в `comment_task`; не пересылать в raw API `field_updates`. |
| `$duration` | Длительность выполнения | **Да** | Рассчитывается вместе со сроком. |

## 7. Работа с прямым SDK PyrusApiClient

При создании сложных административных сервисов или диалоговых ботов допускается прямое использование класс `PyrusApiClient`.

```ts
const api = new PyrusApiClient(request.access_token, request.api_url);
```

### Безопасное применение прямых методов SDK

```ts
// Загрузка полного определения формы (с иерархией полей и каталогами)
const formResponse = await api.forms.get({ id: formId });

// Загрузка справочника
const catalogResponse = await api.catalogs.get({ id: catalogId });

// Перенос/скачивание файла
const fileBuffer = await api.files.download({ id: fileId });
const uploadResult = await api.files.upload(fileBuffer, "document.pdf"); // Возвращает guid

// Поиск задач в реестре по фильтру
const registry = await api.forms.getTasks(formId, { include_archived: false });

// Чтение состава роли
const roleInfo = await api.role.get({ id: roleId }); // roleInfo.member_ids
```

## 8. Безопасная работа с типами данных Pyrus

| Тип поля | Особенности чтения | Особенности записи | Главный подводный камень |
| --- | --- | --- | --- |
| **Text, Phone, Email** | `field.value` (string) | `{ id/code, value: "текст" }` | Пустое значение — `null`. |
| **Number, Money** | `field.value` (number) | `{ id/code, value: 1500.50 }` | `0` — **заполненное значение**. Проверка `if (!value)` ошибочна! |
| **Checkmark** | `field.value` | `{ id/code, value: "checked" }` | Принимает `"checked"` / `"unchecked"`. |
| **Multiple Choice** | `value.choice_ids`, `choice_names` | `{ id/code, value: { choice_id: X } }` | Брать `choice_id` динамически из `get_multiple_choice_dict()`. Не хардкодить ID. |
| **Catalog** | `value.item_id(s)`, `item_names`, `rows` | `{ id/code, value: { item_ids: [10] } }` | В задаче нет метаданных о колонках; поиск делать через `get_values_for_catalog()`. |
| **Form Link** | `value.task_id(s)`, `subject` | `{ id/code, value: { task_id: 123, task_ids: [123], subject: "Заявка #123" } }` | Заполнять все 3 свойства для корректного отображения ссылки. |
| **Person** | `value` (объект `Person`) | `{ id/code, value: { id: 777 } }` | `get_info_by_id` умеет разворачивать ролевые ID в список пользователей. |
| **Date / Due Date** | `field.value` (Date / String) | `{ id/code, value: "2026-08-07" }` | Сравнивать даты только через `isSameDate` / `normalizeDate`, а не `===`. |
| **File** | `value` (массив `AttachedFile`) | `{ id/code, value: [{ id: 1 }, { guid: "..." }] }` | Существующие файлы идентифицировать по `md5`. Новые файлы загружать через `files.upload()`. |
| **Table** | `field.value` (массив `ExtendedTableRow`) | `{ id/code, value: rows }` | Таблицы обновляются **целиком**. Сравнивать строки по `row_id`, а не по индексу. |

## 9. Специализированные шаблоны и серверные боты проекта

### 1. CopyBot v5.0 (Бот копирования)
Готовый декларативный движок переноса данных между задачами и таблицами.
- **Главные особенности**: Защита от зацикливания (пары задач обрабатываются не более 1 раза), каскадный перенос, автоматическое создание целевых задач при отсутствии (`form_rules`), агрегация строк таблиц (`sum`, `avg`, `min`, `max`, `count`, `first`, `last`).
- **Ключевой метод**: `copy_from_task(bot, task, rules, comments)`.

### 2. Маршрутизатор
Автоматизирует сложные схемы согласования, возвраты на доработку и ведение динамических таблиц листа согласования.
- **Правила**: `revision_settings` (при «Против» сбрасывает визы и запрашивает повторно), `stop_settings` (расчёт процента отклонений или вето), `registration_settings` (заполнение итоговой таблицы согласования).

### 3. Мониторинг ответственных
Обеспечивает непрерывную синхронизацию системного ответственного Pyrus с контактными полями формы или участниками текущего этапа.
- **Особенность**: Правила выбираются по принципу **последнего совпавшего**, что позволяет задать глобальное правило для всей формы и переопределить его на конкретном этапе.

### 4. Диалоговый бот (`reference/legacy_bots/dialog_bot.ts`)
Ведёт интерактивный диалог с клиентом через внешние каналы (Telegram, Viber, Email).
- **Паттерн сохранения состояния**: Потенциально длинные сценарии хранят JSON состояния в техническом поле формы (получаемом по коду из `form.fields`).
- **Служебный отвечик**: В каждом ответе обязательно сохраняется исходный `channel` комментарий, иначе клиент не получит ответ во внешнем мессенджере.

## 10. Полезные служебные функции и утилиты

В проекте сформирована библиотека готовых проверенных функций:

```ts
// 1. Глубокое рекурсивное копирование по значению (до модификации объектов)
const snapshot = copy_by_value(target.value);

// 2. Сравнение двух значений полей на фактическое изменение (с учётом md5 файлов и row_id таблиц)
if (same_value(oldField, newField) === true) return null;

// 3. Универсальный поиск вариантов каталога по тексту с фильтрацией дублей
const catalogVal = await get_values_for_catalog(bot, ["Москва"], fieldInfo);

// 4. Безопасное сравнение дат без учёта времени
if (isSameDate(dateA, dateB)) { ... }

// 5. Получние списка Email всех участников (включая участников ролей)
const emailsCSV = await get_emails(bot, personIdOrRoleId);

// 6. Получение вариантов выбора Multiple Choice в виде словаря
const choicesDict = await bot.get_multiple_choice_dict("status_code", task);
```

## 11. Официальное логирование, отладка и отслеживание ошибок

1. **Консольный вывод `console.log(...)`**:
   - Является **штатным средством отладки** Pyrus.
   - Все вызовы `console.log`, `console.error`, `console.warn` автоматически перехватываются сервером Pyrus и записываются как **события бота** в его профиле (раздел «Журнал событий»).

2. **Защита от зацикливания собственных комментариев**:
   - Бот **обязан** игнорировать комментарии, автором которых является он сам:
   ```ts
   const lastComment = task.comments?.at(-1);
   if (lastComment?.author?.id === request.user_id) return null;
   ```

3. **Служебные debug-комментарии в задачу**:
   - Использовать только при крайней необходимости на этапе разработки. Маркировать префиксом `[BOT-DEBUG]`. Не отправлять их во внешние каналы (`channel` не передавать).

## 12. Предпусковой чек-лист готовности бота

- [ ] **Коды полей**: Все используемые поля формы, таблицы и колонки имеют уникальные и корректные `code` в конструкторе формы Pyrus.

- [ ] **Защита от петли**: Добавлена проверка `author.id !== request.user_id`.
- [ ] **Исключения**: Код у Comparison/CopyBot обрабатывает возможные текстовые строки ошибок (`typeof res === "string"`).

## 14. Рекурсивный разбор схемы формы и симуляция тестирования (Паттерн order_bot.ts)

### 1. Золотое правило полной гидратации формы (`FormModel` + `TaskModel`)
При работе с серверными скриптами **нельзя** искать поля простым перебором верхнего уровня `task.fields`. 
Поля могут находиться внутри контейнеров-заголовков (`title` / `group`), вариантов выбора (`options`) или колонок таблиц (`columns` / `cells`).

Каждый серверный скрипт бота должен использовать рекурсивную модель разбора:
```ts
// 1. Полная схема формы (из API или fallback из задачи)
const form = await FormModel.load(client, formId, task.fields);

// 2. Полный рекурсивный индекс всех значений задачи
const values = new TaskModel(task.fields);

// 3. Получение значения любого поля (даже глубоко вложенного) по коду
const stateRaw = values.getByCode(form, "technical_bot_state");
```

### 2. Симулятор и тестовая среда Pyrus (`src/lib/testing/pyrus_simulator.ts`)
Для локальной проверки логики скриптов до деплоя в Pyrus используется эмулятор [src/lib/testing/pyrus_simulator.ts](src/lib/testing/pyrus_simulator.ts) и запуск тестов:

```bash
# Запуск локальных тестов скриптов и симулятора Pyrus
npm run test
```

Сеть в симуляторе подменена. Бот создаёт `new PyrusApiClient(...)` внутри себя, поэтому клиент-заглушку ему не передать — зато весь `pyrus-api` ходит через глобальный `fetch`, и на время вызова подменяется именно он. Ответы Pyrus объявляются маршрутами:

```typescript
const { response, network } = await simulateServerBot(botHandler, request, {
  routes: [
    { method: "GET",  url: "/forms/888",           body: FORM_SCHEMA },
    { method: "POST", url: "/tasks/99001/comments", body: {} }
  ]
});

// Забытый маршрут не должен выглядеть как «Pyrus недоступен»:
check("все обращения к Pyrus объявлены", network.unmatched.length === 0, network.unmatched);
```

Незаявленный вызов получает код 599 и попадает в `network.unmatched`. Проверять этот список обязательно: без проверки бот, ушедший за неожиданными данными, тихо отработает по ветке «сервис недоступен», и тест это одобрит.
