# ИИ-ассистент инженера внедрения Pyrus

Репозиторий ведёт документацию, ТЗ, спецификации форм, серверных ботов и формные скрипты для клиентов Pyrus и синхронизирует всё это с Базой знаний Pyrus, которая работает как общий хаб между инженерами.

Копия проекта лежит локально у каждого инженера. Общее состояние расходится через git и через синхронизатор Базы знаний. Работать можно из Claude Code, Antigravity или Kilocode — правила проекта попадают в контекст модели автоматически.

## Первый запуск на новом ПК

```powershell
powershell -ExecutionPolicy Bypass -File .\bootstrap.ps1
```

Скрипт проверит Node.js (и предложит поставить, если его нет), выполнит `npm install`, создаст `.env` из `.env.example`, прогонит `npm run check` и сверится с Базой знаний. Запускать повторно безопасно: существующий `.env` не трогается.

На PowerShell, а не на TypeScript, — потому что на чистом ПК Node.js ещё нет. На не-Windows те же шаги выполняются вручную:

```bash
node --version          # нужен 20+
npm install
cp .env.example .env    # логин и PYRUS_SECURITY_KEY вписывает инженер лично
npm run check
npm run kb:sync:dry
```

У каждого инженера **свой** ключ интеграции Pyrus — иначе в Базе знаний не видно, кто автор правки.

## Начало рабочей сессии

```bash
git pull
npm run kb:sync         # синхронизация с Базой знаний ДО правок
```

`PULL` означает, что статью изменили в Pyrus — прочитайте её заново. `CONFLICT` останавливает работу до ручного разбора: рядом с файлом появится `.remote.md` с удалённой версией.

## Команды

```bash
npm run new:form -- --client=01_Демо_кабинет --name="Заказы пиццы"   # комплект статей новой формы
npm run pyrus:dump      # состав формы или справочника из API: -- --forms, --form=NN, --catalog=NN
npm run map             # перестроить карту связей форм и скриптов
npm run check           # типы, тесты, правила документации и свежесть карты связей
npm run lint:docs       # только Фундаментальные правила 1-5
npm run kb:sync         # синхронизация с Базой знаний
npm run kb:sync:dry     # посмотреть, что произойдёт, без записи
npm run kb:dump         # дерево Базы знаний
npm run docs:agents     # перегенерировать документацию агентов
npm run agents:config   # перегенерировать CLAUDE.md / AGENTS.md / .kilocode
```

## Структура

```
clients/NN_Клиент/
    UserDocs/NN_Форма/      пользовательская документация
    TechDocs/NN_Форма/      ТЗ, спецификация полей, маршрутизация
    Forms/NN_Форма/scripts/ исходный код ботов и скриптов
solutions_bank/             переиспользуемые наработки по всем клиентам
    bots/  form_scripts/  functions/  solutions/
    scripts/                скрипты автоматизации репозитория
.agents/                    роли, правила и навыки агентов — единственный источник
project_docs/               выгружаемая копия .agents/ для Базы знаний
templates/form/             канонический комплект статей формы для npm run new:form
src/lib/                    Банк функций: код, из которого собираются боты
reference/                  чужие образцы и старые дампы: не документация, не синхронизируется
```

`CLAUDE.md`, `AGENTS.md` и `.kilocode/rules/` **генерируются** из `.agents/` — правьте источник, а не их.

## Роли агентов

- **pyrus_orchestrator** — встречает задачу, готовит рабочее место, маршрутизирует работу.
- **pyrus_spec_analyst** — собирает требования, ищет краевые случаи, утверждает спецификацию.
- **pyrus_reverse_documentarian** — восстанавливает документацию по готовому решению.
- **pyrus_bot_developer** — серверные боты (`BotHookRequest`).
- **pyrus_form_script_developer** — клиентские скрипты формы (`form.onChange`).
- **pyrus_tech_writer** — пользовательская документация человеческим языком.
- **pyrus_doc_reviewer** — смысловая проверка документации: то, чего не видит линтер.
- **pyrus_bank_curator** — что попадает в Банк функций и на каких условиях.

## Правила документации

Проверяются машиной в `npm run lint:docs`, в pre-commit и в GitHub Actions — не на память. Локальный хук обходится флагом `--no-verify` и на чужом ПК может быть не установлен, поэтому те же проверки выполняются на стороне GitHub при каждом push и pull request:

1. Любое изменение сопровождается записью в `История_изменений` своего раздела.
2. В каждой папке `_index.md` со ссылками на все её статьи.
3. У каждой папки документации есть и оглавление, и история изменений.
4. Заголовок статьи задаётся только в YAML `title`. H1 в теле запрещён — Pyrus подставляет заголовок сам.
5. Конфигурация агентов отражается в Базе знаний через `npm run docs:agents`.

Идентичность статьи (`pyrus_id`, `synced_at`, `synced_hash`) живёт в YAML-заголовке документа и ведётся синхронизатором — руками не трогать.
