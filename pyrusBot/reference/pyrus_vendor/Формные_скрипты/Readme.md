# Скрипты форм Pyrus

Данный раздел содержит описание и примеры клиентских скриптов, используемых в формах Pyrus. Информация основана на базе знаний `Скрипты.xlsx`.

## Обзор архитектуры

Скрипты форм в Pyrus исполняются на стороне клиента (в браузере пользователя) и позволяют реализовывать интерактивную логику:
*   Управление видимостью полей.
*   Валидация введенных данных перед сохранением или переходом на этап.
*   Автоматический расчет значений (суммы, даты, сроки).
*   Динамическая фильтрация справочников.
*   Взаимодействие с данными других форм через API (`fetchSelfRegister`, `fetchRegister`).

### Основной механизм: `form.onChange`
Скрипты реагируют на изменения полей.
```javascript
form.onChange(['КодПоля1', 'КодПоля2'], true)
    .setValue('ЦелевоеПоля', state => {
        const [val1, val2] = state.changes;
        return val1 + val2;
    });
```
*   Первый аргумент — массив кодов полей, за которыми следим.
*   Второй аргумент (`true`) — запускать ли скрипт при открытии формы (инициализация).

## Справочник функций

| Функция | Описание |
| :--- | :--- |
| `setValue(field, fn)` | Устанавливает значение в поле. Если вернуть `null`, поле блокируется. |
| `setValues(fields, fn)` | Массовая установка значений (принимает массив кодов). |
| `setVisibility(fields, fn)` | Управляет видимостью полей (возвращает `true`/`false`). |
| `validate(field, fn)` | Выполняет проверку. Возвращает `{ errorMessage: "Текст" }` при ошибке. |
| `setFilterAsync(field, fn)`| Фильтрует значения в справочниках (возвращает `values: [...]`). |
| `setStatus(fn)` | Меняет статус задачи (выбор в поле типа Статус). |

## Карта скриптов (примеры из Базы Знаний)

Ниже приведен обзор наиболее полезных решений, найденных в `Скрипты.xlsx`.

### 1. Видимость и доступ
*   **Скрытие по ролям**: Скрытие настроек или технических полей от участников определенных ролей (например, "Исполнитель").
*   **Скрытие по этапу**: Показ полей только на определенных шагах маршрута (`state.currentStep`).
*   **Внешние формы**: Скрытие полей для неавторизованных пользователей (проверка `state.commenter`).

### 2. Валидация
*   **Контрольные суммы**: Полная реализация проверки ИНН и СНИЛС.
*   **Маски**: Проверка форматов номеров сертификатов, IP-адресов через регулярные выражения.
*   **Таблицы**: Запрет дубликатов в строках таблицы (с использованием фильтрации).
*   **Файлы**: Ограничение количества загружаемых файлов в поле типа "Файл" (например, не более одного).

### 3. Расчеты и сроки
*   **Возраст**: Автоматический учет лет на основе даты рождения.
*   **Сроки**: Прибавление N дней/часов к дате (`date.setDate(date.getDate() + 365)`).
*   **Рабочие дни**: Проверка количества рабочих дней до начала отпуска (через внешний календарь-справочник).
*   **Периодические суммы**: Расчет годовой/квартальной суммы на основе ежемесячной.

### 4. Работа с таблицами
*   **Агрегация**: Суммирование значений по колонкам или подсчет отмеченных галочек.
*   **Текст из строк**: Объединение значений из всех строк таблицы в одну строку через запятую.
*   **Нумерация**: Подсчет общего количества строк в таблице.

### 5. Утилиты и форматирование
*   **Сумма прописью**: Конвертация чисел в текст на русском языке (рубли и копейки).
*   **Инициалы**: Сборка ФИО из отдельных полей Фамилия, Имя, Отчество.
*   **Телефон**: Нормализация номера (удаление лишних символов, приведение к формату 7XXXXXXXXXX).
*   **Часовые пояса**: Пересчет времени в московское для фиксации в текстовом поле.

## Лучшие практики и советы

1.  **Оптимизация запросов**: Если скрипт использует `getCatalog`, сохраняйте Promise в переменную вне блока `onChange`, чтобы не делать лишние сетевые запросы при каждом изменении поля.
    ```javascript
    let catalog_promise = form.getCatalog(12345);
    form.onChange(...).someAsyncFunction(async state => {
        const items = await catalog_promise;
        // ...
    });
    ```
2.  **Отладка**: Используйте `console.log(state)` для просмотра структуры данных. Все изменения доступны в `state.changes`.
3.  **Безопасность**: При доступе к глубоко вложенным свойствам используйте опциональную цепочку (`?.`), например: `state.commenter?.role_ids`.
4.  **Мобильная версия**: Старайтесь не злоупотреблять `setVisibility`, так как в мобильном приложении это может работать иначе; лучше использовать стандартные настройки видимости Pyrus там, где это возможно.
