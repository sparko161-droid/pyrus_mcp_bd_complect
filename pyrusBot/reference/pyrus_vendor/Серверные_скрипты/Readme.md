Этот репозиторий содержит набор серверных скриптов для автоматизации процессов в Pyrus. Все скрипты построены на базе общей архитектуры, минимизирующей дублирование кода при работе с API.

## 🏗 Архитектура и паттерны

Все современные скрипты используют класс-обертку **`ExtendedClient`**, который расширяет стандартный `PyrusApiClient`.

### 1. Работа с полями по кодам (`named_fields`)
Вместо использования ID полей (которые меняются от формы к форме), мы используем **коды полей**.
- Функция `fix_task` преобразует стандартную задачу Pyrus в `ExtendedTask`.
- Доступ к полю: `task.named_fields["MY_FIELD_CODE"].value`.

### 2. Системные поля (`$`)
`ExtendedClient` автоматически добавляет виртуальные поля для удобного доступа к метаданным задачи:
- `$task_id` — ID задачи.
- `$task_link` — прямая ссылка на задачу.
- `$current_step` — номер текущего этапа.
- `$assignee` — текущий ответственный.

### 3. Настройки через `bot_settings`
Логика скриптов не зашита в код, а выносится в JSON-настройки самого бота в Pyrus. Это позволяет менять правила работы без пересборки скрипта.

### 4. Логирование ошибок
Скрипты используют объект `error_log`. Если в процессе работы (например, при копировании) возникает ошибка, бот пишет сообщение об этом прямо в ту задачу, которая вызвала ошибку, но не чаще раза в 5 комментариев (защита от спама).

## 🚀 Руководство по разработке нового скрипта

1.  **Возьмите за основу** файл из папки `Шаблонный бот`.
2.  **Определите логику** в функции `function_to_do(bot, full_task, settings)`.
3.  **Используйте Helper-функции**:
    - `copy_by_value(obj)` — для глубокого копирования объектов (включая Date).
    - `prepare_approval_list(task)` — для получения карты согласования по этапам.
    - `get_info_by_id(id)` — для получения данных профиля пользователя или роли.

> [!TIP]
> Всегда используйте `bot.comment_task(id, comment)` вместо прямого вызова API. Это гарантирует, что кеш задач обновится корректно, а пустые поля типа "Выбор" будут обработаны правильно.
