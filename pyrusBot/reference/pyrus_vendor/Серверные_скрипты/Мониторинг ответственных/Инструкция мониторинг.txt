             "steps": [1,2],
            "field_code": "resp",

            "only_field": false,
            "auto_step" : 1,
            "exlude_resp": [4]
        }
    ]

В настройках в атрибуте rules передаются правила, которые бот применяет к задачам. Каждое правило состоит из параметров:
form_ids - обязательный параметр, массив id форм, в которых может работать бот. 
steps - необязательный параметр, массив из номеров этапов, на которых применяется правило. Полезно, если в течение жизни задачи надо подставлять разных ответственных из разных полей. Если не указывать или указать пустой массив, правило будет применяться на всех этапах
field_code - обязательный параметр, поле типа Контакт. Табличные поля НЕ поддерживаются
only_resp - необязательный параметр, если нужно принимать во внимание значения только из Системного ответственного. Если системный ответственный менялся в задаче, то поле всегда будет принимать последнее установленное значение системного ответственного
only_field - аналогично предыдущему параметру, только для поля
auto_step -  если у вас есть этап с режимом очереди и нужно закрепить пользователя, который его утвердил в качестве ответственного, укажите этот этап в параметре. Необязательно
exlude_resp - при переходе на этот этап ответственный будет удалён. Например, у вас есть процесс обработки заявки и после 4 этапа он переходит в другой отдел. В таком случае поставьте steps = [1.2.3] и удаление при переходе на 4 этап

Если под вызов из задачи попадают несколько правил, то используется последнее из перечисленных. Например, мы хотим, чтобы на втором этапе системный ответственный синхронилось с полем Ответственный исполнитель, а на всех остальных с полем Контролёр. В таком случае, мы делаем два правила: в первом указываем step: [2], а во втором вообще не используем параметр steps.
